# ADR-0009: Presentation rules for the game UI overhaul

**Status:** Accepted
**Date:** 2026-10-23

## Context

The vertical slice played well but looked like a web page: flat panels, numbered lines, a black
caption bar, modal cards. The owner asked for a game UI built on three pillars (the weight of the
stamp; the dead tell their tale; a desk at the end of the world). The planning panel's decisions
are in `docs/plans/game-ui-ledger.md` (D1–D51). Four of them are rules that outlive the feature
and bind later work, so they are recorded here.

## Decision

1. **The telling never tells.** Every soul's lines are told the same way: the same sheet, the same
   pace, a voice pitch derived from a hash of the soul's name. No presentation that happens
   before a thread is made may read `legal_realm`, `worthy_realm` or `liar` (ledger D1, D4; GDD
   §1 test 2, slice D45). A test diffs the telling of a liar and a hero with the same lines.
2. **The clock waits for the telling.** The day clock runs from the end of the telling (or its
   skip), plus action costs (D5; GDD §3.7 amended). The gate is in the desk system, not in core,
   so the text harness is unchanged.
3. **One presentation gate.** A scene-owned `PresentationGate` is the only owner of "a
   presentation is in progress". A press during a consuming presentation (a telling, a written
   reveal, the dawn card) finishes it and does nothing else; a press during the slam window is
   ignored; otherwise the press acts. Pause and focus loss stop presentations through the gate,
   never through `SceneTree.paused` or `Engine.time_scale` (D27, D51; plan §3).
4. **Sound and options provenance.** New sounds are generated by `tools/audio/synth_sounds.py`
   into 16-bit WAV with Python's standard library, credited as generated; the two Kenney CC0
   sounds stay (D25, D50). Options (text speed, reduce motion, volume, mute) live in
   `user://options.cfg` with validated defaults; on the web a blocked store falls back to defaults
   (D37). No other persistence exists.
5. **Timed cues, not frame counts.** Presentation cues (a squash, a ring, a burst, a gutter label) are
   timed in seconds through tweens the gate watches, never counted in frames, and tests bound
   their waits by elapsed time. `project.godot` caps `run/max_fps` at 60 so no cue is shorter
   than a frame on a fast machine (ledger D56).
6. **Words.** The caption strip is the *clerk's note*; the between-days book is the *day-book*;
   *Ledger* keeps its one meaning, the tray of god requests (D1).

## Alternatives considered

- A second font file for titles: rejected for licensing and download work; titles are hand-placed
  pixel capitals (D3, ADR-0008 stands).
- Downloaded CC0 sound packs: rejected to keep provenance in the repository (D25).
- `Engine.time_scale` for the slam's hit-stop: rejected because it would also stop the tween meant
  to release it; the hold is a tween interval (plan §3).

## Consequences

- Slice decisions D10, D11, D21, D31, D33, D34 and D53 are amended by the ledger rows that cite
  them; the slice ledger is history, this ledger is current.
- Every new presentation must register with the gate or it will neither skip nor pause correctly.

**Revisit when:** a presentation needs to read the truth (it must not; this ADR is the reason), a
target platform cannot write `user://`, or the owner's play finds the telling too slow even at
"fast".
